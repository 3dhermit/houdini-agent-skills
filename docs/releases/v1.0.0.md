# v1.0.0 — six Houdini agent skills on one version-aware `hou` wrapper

The first release of a skill layer for Houdini agents: JSON-schema-validated
actions, structured error envelopes, and tests that run headless against a real
Houdini license instead of prose that sounds right.

**Test state at this tag:** 24 Tier A tests green on system Python (no Houdini
needed), 30 Tier B tests green under `hython` on Houdini 22.0.368.

## Skills

| Category | What it does |
| --- | --- |
| `sop-automation` | create/chain nodes, bind parms by verified candidate names, find nodes, read geometry stats (piece count by `name`, not prim count) |
| `vex-helper` | VEX templates plus two tiers: static `lint`, and `validate` that creates a real Attribute Wrangle and cooks it so the Houdini compiler — not a regex — decides |
| `simulation-tools` | `dopnet` containers, SOP sources/solvers (`pyrosource`, `pyrosolver`, `rbdmaterialfracture`, `rbdbulletsolver`, `flipsource`, `flipsolver`, `vellumsolver`) and File Cache setup |
| `rendering` | Karma ROP configuration (resolution, `picture`, `samplesperpixel`, `trange`/`f1`/`f2`). Configures only — never renders |
| `usd-pipeline` | SOP → SOP Import LOP → USD Output ROP → a real `.usda` on disk, verified by bytes and sibling layers |
| `troubleshooting` | a knowledge base of verified `hou` API and parm mistakes, with `hou_lookup` and `explain_error` that need no Houdini at all |

Every action has an input schema in `skills/<category>/meta.json`; the full
catalog with trigger prompts is in `SKILL_REGISTRY.md`.

## Supported Houdini versions

- Declared floor: **19.5+**
- **Verified on: 22.0.368 only.** Every parm name and node type in the docs is
  read off that build and pinned by
  `tests/test_tier_b.py::TestVerifiedApiFacts`, so a SideFX rename fails a test
  instead of silently shipping a wrong table. See `docs/verified-api.md`.

## Known v1 limitations

- 19.5/20.x/21.x are supported by intent, not by test. Where a name differs,
  skills report `unresolved_parms` / `unknown_parm` with real suggestions
  rather than guessing.
- Tier B tests need a licensed, self-hosted runner. GitHub-hosted runners can
  not legally install Houdini, so CI runs Tier A + registry checks there.
- `simulation-tools` builds the graph and caches; it does **not** step a
  simulation and never claims one advanced.
- `rendering` never auto-renders. `mantra` is not registered on 22.0.368 and no
  Karma ROP parm selects CPU vs XPU — the skill says so in `xpu_note` instead of
  inventing a parm.
- No APEX/crowds, Copernicus, TOPs/PDG or lookdev automation in v1.

## Install / use

```bash
python -m houdini_skills.cli --list
"<Houdini>/bin/hython" -m houdini_skills.cli sop-automation grid_bevel \
    --json '{"container":"demo","size":[4,0,4],"divisions":6,"bevel_width":0.05}'
```
