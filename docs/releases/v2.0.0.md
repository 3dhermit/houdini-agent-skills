# v2.0.0 — every claim in this repo now has a live Houdini run behind it

A MAJOR bump, and not for polish: nine live passes inside a running Houdini 22.0.368
GUI session disproved claims v1.0.0 made confidently, and the fixes changed payload
schemas and result envelopes. Under this repo's own rule (`README.md` → *Semantic
versioning*, `docs/contributing.md`), an action's schema or result envelope changing
is a MAJOR. The knob half of that statement is machine-generated by diffing each
`meta.json` against the `v1.0.0` tag; the envelope half is in `SKILL_REGISTRY.md` →
*Migrating from v1.0.0*.

**Test state at this tag:** 34 Tier A tests green with no Houdini present (local 3.14;
CI on 3.10/3.11/3.12), **74 Tier B tests green under `hython` on Houdini 22.0.368**
(skipped=1), plus nine live GUI passes that create, cook, read back, and delete their
own nodes — each pass ending with node count restored exactly and `saved: false`.

## Breaking changes

Schema diff (`v1.0.0` → now, generated from git, not memory):

| action | removed | added |
|---|---|---|
| `simulation-tools.pyro` | `cache_dir`, `resolution_scale` | `source_radius`, `voxel_size`, `density` |
| `simulation-tools.flip` | — | `site_count` |
| `rendering.configure` | `path` | `camera` |
| `usd-pipeline.export` | `unpack` | `default_prim`, `flatten_sop_layers`, `keep_layers_together` |
| `usd-pipeline.sopimport` | `prim_path` default `/world/asm` | — |
| `vex-helper.validate` | — | `node_type` (`attribwrangle` / `volumewrangle`) |

The removals were not tidying. Every one was a **knob nothing read**: `rendering`
shipped `path` while the fresh Karma ROP has 405 parms and none named `path`;
`pyro` shipped `cache_dir`/`resolution_scale` while the Volume SOP it drives has
`divsize`, not `voxelsize`; `usd-pipeline.export` shipped `unpack` with no parm behind
it. A new CI gate, `tools/check_payload_knobs.py`, fails any `payload_schema` key with
no reader in the handler chain, so this class of bug cannot return silently.

Result envelopes now carry what Houdini reported rather than what was asked for:
`applied[knob] = {parm, requested, kept, eval}` plus `drift`/`drift_note`,
`parm_report` for the pyro chain, `prim_types` inside geometry stats, `stage_prim_paths`
/ `stage_prim_stats` for SOP Import, and `created_nodes` on every builder so callers
can undo exactly what was made.

## What the live session disproved

Each row was asserted in v1.0.0 prose, then measured on 22.0.368.

| v1.0.0 claim | verified reality |
|---|---|
| pyro density authored by a wrangle inside `pyrosource` | that node has **no `snippet` parm**; the recipe now authors density as a Volume SOP field (`name`/`type`/`rank`/`initialval1`/`divsize`) fed into the Pyro Solver's `Sources` input |
| Volume SOP voxel size = `voxelsize` | no `voxelsize`, no `gridtype`; the real parms are `divsize` + `divsx/divsy/divsz` |
| Karma frame range settable with `parm.set()` | `f1`/`f2` arrive **channelled** (`$FSTART`, `$FEND`); a plain `set()` is a silent no-op. Fix: `deleteAllKeyframes()` then `set()` — the skill now does it and reports `cleared_keyframes` |
| a FLIP builder's dopnet was part of the sim graph | SOP solvers have no dop parms; the dopnet was decoration, so it is gone and the FLIP source's real shape is reported (`Volume: 1`, `PolyLine: 2582`) |
| SOP Import `prim_path` places prims on the stage | `primpath` binds and reads back `/world` while the prims stay at `/<node>/mesh_0` — at the importer **and** one LOP downstream. Payload returns both and a note when they disagree |
| a VEX snippet in the wrong wrangle "does nothing" | it writes an attribute **in the wrong place**: point/prim/detail class each add `density` there, all with 0 errors; only `volumewrangle` edits the volume field |
| menu read-back is ambiguous (`rawValue()` might be index) | `rawValue()` is the identifier/label, `eval()` is the index. The earlier "0" was our helper publishing `eval()` under the key named `kept` |
| a refusal message was enough | `SkillFailure.__str__` dropped its own `hint`; agents print exceptions, not `to_result()`. Suggestions like `closest: polyextrude, ...` now appear in the string |

Names this build refused when an agent invented them, now pinned in docs and tests:
`polyexdiv` (real family: `subdivide`, `divide`, `tridivide`, `edgedivide`,
`unsubdivide`), `matl_name` on the SOP `material` node, `hou.LopNetwork.stage()` and
`displayLop()` (stage accessors are on LOP nodes; the container type is `lopnet`, not
`lop`), `hou.Parm.label()`, `hou.Geometry.globalAttribsNames()`,
`hou.playbar.frame()`, `hou.pwd().frame()`, `hou.Volume.fieldNames()` /
`volumePrimitive()` / `volumefields()`.

Also documented: `hou.Parm.menuItems()` is not a menu test — on `volumewrangle.snippet`
it returns the parm's default text instead of raising; use
`parmTemplateGroup().find(name)` being a `MenuParmTemplate`. And the VEX compiler's
three tiers: `vector p = {@P.x, 2.0, 1.0};` fails to **cook** (lint now catches it),
`ch("missing_parm")` compiles then fails the cook, `nosuchfunction(@P)` fails to
compile while lint stays clean — so a clean lint can never certify validity.

## What is still out of scope

- 19.5–21.x is a declared floor, never tested; names are read off 22.0.368.
- Nothing steps a simulation; `rendering` configures and never renders.
- Voxel *values* are unreportable on this build — no verified `hou.Volume` field
  accessor exists, so the pyro payload lists them under `not_verified` rather than
  implying a check that did not happen.
- No APEX/crowds, Copernicus, TOPs/PDG or lookdev automation.

## Action coverage

`32/32` declared actions have been executed inside a live session; the coverage audit
(`32 declared, 0 never run`) is why this release can say *verified* instead of
*written*. Five actions had never been run live before this cycle —
`sop-automation.chain`, `usd-pipeline.sopimport`, and `vex-helper`'s `list_templates`,
`lint`, `explain` — and running them is what found the SOP Import and hint-text
defects above.
