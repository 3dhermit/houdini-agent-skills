## rendering

Configure a Karma (or mantra) Render Output ROP: driver, resolution, frame range, output path, AOV requests. Config only - it does not silently render.

**Trigger prompts that should select this skill**
- "set up a karma render"
- "configure aovs"
- "set render resolution"
- "point a render rop at my geo"

**Actions** (payload schema lives in `skills/rendering/meta.json`)
- `configure` - required: none; optional: aovs, camera, container, engine, frames, output_path, resolution, samples
- `inspect` - required: path; optional: none
- `list_engines` - required: none; optional: none

**Examples**

## Known limitations (v2.0.0)

- Verified only on 22.0.368; the 19.5-21.x floor is declared, not tested.
- `simulation-tools` does not author DOP graph contents and never steps a sim.
- `rendering` never renders; Karma AOV authoring is out of scope.
- `usd-pipeline` proves one file landed; layer stacks / MaterialX are out of scope.
- Karma requires H20+, so the 19.5 floor gets an explicit `engine_unavailable` error.
- Voxel *values* cannot be read back on this build: no verified `hou.Volume` field accessor exists (`fieldNames` / `volumePrimitive` / `volumefields` all raise), so the pyro recipe reports them under `not_verified` instead of claiming a verification it cannot do.
- `usd-pipeline.sopimport` can bind the LOP's `primpath` parm but cannot move the authored prims with it on 22.0.368; the payload says so beside the stage paths it actually read.
- `vex-helper.lint` is a pre-filter, not a validator: its verified-call list is not Houdini's builtin set, and a clean lint never certifies that VEX compiles.

## Migrating from v1.0.0 (MAJOR)

Knob changes, generated by comparing each `meta.json` against the `v1.0.0` tag:

| action | removed | added |
|---|---|---|
| `simulation-tools.pyro` | `cache_dir`, `resolution_scale` | `source_radius`, `voxel_size`, `density` |
| `simulation-tools.flip` | - | `site_count` |
| `rendering.configure` | `path` (bound nothing; the ROP has 405 parms and no such name) | `camera` |
| `usd-pipeline.export` | `unpack` (no parm read it) | `default_prim`, `flatten_sop_layers`, `keep_layers_together` |
| `usd-pipeline.sopimport` | `prim_path` schema default `/world/asm` (a silent binding that provably does not move prims) | - |
| `vex-helper.validate` | - | `node_type` (`attribwrangle` / `volumewrangle`) |

Result envelopes grew read-back keys. Treat what Houdini reports, not what was requested:

- `rendering.configure`: `applied[knob]` is now `{parm, requested, kept, eval}`; new `drift`, `drift_note`, `cleared_keyframes` (`f1`/`f2` arrive channelled as `$FSTART`/`$FEND`, and a plain `set()` on them is a silent no-op until the channels are deleted).
- `simulation-tools.pyro`: `parm_report` per knob, `solver_wiring`, `source_stats`, `not_verified`. The old `pyrosource` + density-wrangle recipe was a lie - that node has no `snippet` parm.
- `usd-pipeline.sopimport`: `prim_path` is replaced by `prim_path_requested`, `prim_path_kept`, `prim_path_parm`, plus `stage_prim_paths`, `stage_prim_stats` and a note when the two disagree.
- `sop-automation.set_parms`: entries carry `kept` and the call reports `drift`; for menu parms `rawValue()` is the label and `eval()` is the index.
- `sop-automation.geo_stats` and the sim builders: `prim_types` (a FLIP source reports `Volume: 1, PolyLine: 2582` - a prim count alone hid that).
- `vex-helper.list_templates` / `template`: each carries `node_type`, `wrangle_kind` and a `binding_note`; `explain` line entries gained a `note`.
- Failures: `SkillFailure.__str__` now includes the hint and source, so a refusal that carried 'closest: polyextrude, ...' suggestions actually shows them (agents usually print the exception, not `to_result()`).
